# Локальный комплект HW1 ASR

Этот документ описывает состав и использование итогового архива. Сам по себе он не подтверждает завершение приёмки: окончательные результаты и хеши находятся в `FINAL_RESULTS.json`, `manifest.json` и `SHA256SUMS` данного выпуска.

## Проверка и исходники

Сначала сравните SHA-256 файла `reproduction.zip` с переданным рядом хешем. После распаковки проверьте файлы по `SHA256SUMS`. Хеш самого внешнего ZIP передаётся отдельно, чтобы избежать циклической зависимости.

`source.zip` содержит исходники; его можно распаковать в новую папку без Git и авторизации. `source.bundle` содержит историю Git. Имя ветки и точный commit указаны в `manifest.json`; при восстановлении bundle явно задайте эту ветку через `git clone --branch`, затем сравните `git rev-parse HEAD` с manifest. Исходники внутри ZIP и восстановленного bundle проверяются при сборке выпуска.

Используйте Python 3.12. Установка, входной формат `audio/` и необязательные `transcriptions/` описаны в исходниках и notebook. Запускайте команды из распакованной папки исходников. Зафиксированные CPU зависимости и доказательства чистой установки входят отдельными компонентами; GPU и Colab проверки имеют собственные доказательства.

## Выбранная модель и инференс

`model.pt` — окончательно выбранные model-only веса. `resume.pt` — соответствующий полный checkpoint с состояниями оптимизатора, scheduler и RNG. Они не взаимозаменяемы при продолжении обучения. `resources.json` содержит зафиксированные параметры декодирования; не подбирайте их по test.

Для полностью локального инференса укажите `checkpoint` на распакованный `model.pt`, `custom_dir` на папку пользовательского набора и `output_dir` на новую папку предсказаний. Передайте все `inference_overrides` из `resources.json`; если выбран декодер с LM, замените только `lm_path` на абсолютный путь к приложенной `3-gram.pruned.1e-7.arpa.gz`. Остальные параметры декодера оставьте из выпуска. Интернет для скачивания уже приложенных весов и LM не нужен. Без эталонов выдаются только предсказания, метрики равны null.

Итоговые таблицы содержат только полные dev-clean/dev-other/test-clean/test-other. Сохранённые тренировочные JSONL могут содержать subset-мониторинг: он описывает ход обучения и не заменяет итоговые полные метрики.

## Логи, родители и альтернативные веса

`delivery-components-index.json` сопоставляет каждому сохранённому компоненту поле `archive_member`: это имя файла относительно корня распакованного комплекта. Абсолютные пути в поле `path` — историческое происхождение на машине автора; для открытия компонентов они не нужны. Окончательный перечень файлов и их хешей задаёт `manifest.json`.

Логические ZIP логов содержат исходные имена запусков, JSONL, W&B offline и медиа. Архивы родителей и исходных manifests сохранены отдельно. `final_worker8_all_closed_states.tar.gz` сохраняет все четыре финальные best/last model/full пары двух последних запусков. Это content-addressed снимок: `manifest.json` внутри TAR сопоставляет логическое имя файла с SHA-256, а байты лежат в `blobs/<sha256>`. При восстановлении альтернативной пары проверьте SHA и размер обоих blobs, затем сохраните их под соответствующими логическими именами. Не передавайте такой TAR как обычный архив логов.

Точные конфигурации и перенос путей для возобновления описаны в `OVERNIGHT_TRAINING_REPRODUCTION.md` внутри исходников. Набор LibriSpeech загружается отдельно; весь объём аудио в архив сдачи не включён. Сохранённые manifests фиксируют выборку и порядок данных. Воспроизведение всей исторической траектории обучения с нуля на другом устройстве не заявляется.

`REPORT.pdf`, результаты полной оценки, проверки model/full, восстановление bundle и выполненные notebooks объясняют фактическую приёмку. Исторические или диагностические компоненты явно сохраняют исходные статусы и не являются отдельной финальной сдачей.

При подготовке использовалась помощь LLM. Правила курса содержат запрет LLM; техническая воспроизводимость не подтверждает соответствие этому правилу.
