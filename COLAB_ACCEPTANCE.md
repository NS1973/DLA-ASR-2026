# Приёмка итогового Colab

Это порядок проверки, а не свидетельство её завершения. Пилотный запуск с вручную загруженными исходниками и весами не заменяет проверку окончательного demo.

1. Зафиксировать выбранные веса и декодер после полной dev-оценки. Заполнить `resources.json` действительными ссылками и SHA-256; проверить скачивание без cookies. Сохранить commit исходников и хеш notebook.
2. Открыть окончательный `DLA_ASR_Demo.ipynb` в новом Colab runtime, выбрать T4. Зафиксировать Python, PyTorch, GPU и начало проверки. Результат старого runtime не использовать как доказательство свежей установки.
3. До 16:00 репозиторий приватный. Если обычное клонирование недоступно, загрузить собственный архив зафиксированных исходников через Files и распаковать в `/content/DLA-ASR-2026`. Проверить хеш архива. Подготовку доступа описать в отчёте: это дополнительный шаг проверки приватных исходников, а не анонимное клонирование. Не помещать токены в notebook или публичные файлы.
4. В единственное пользовательское поле `DATASET_URL` вставить проверенную ссылку с эталоном:
   `https://drive.google.com/file/d/1lNBQAlVLU3OnMq3GDdfVI8HAdtRiGflr/view`.
   Выполнить все ячейки окончательного notebook без изменения их кода. Проверить установку, SHA ресурсов, встроенный пример, пользовательский инференс, отдельный расчёт метрик и ZIP предсказаний. Сохранить выполненный notebook с outputs и execution_count.
5. Повторить пользовательскую часть со ссылкой без эталонов:
   `https://drive.google.com/file/d/1HKYGtBXU5oB5Y0ixWT_Wze6v4ADF8gDf/view`.
   В наборе три версии одной настоящей train-записи: mono 16 kHz FLAC, stereo 8 kHz WAV и stereo 44.1 kHz MP3. Проверить ровно три исходных ID, отсутствие расчёта WER/CER и отсутствие файлов первого пользовательского набора. Это проверка интерфейса, а не качества обобщения.
6. Сохранить результаты отдельно: выполненный notebook полного запуска с эталоном, outputs повторного запуска без эталонов, SHA-256, параметры и ошибки, если они были. Исправление требует успешного повторного запуска затронутой цепочки; не выдавать неуспешный запуск за итоговый.
7. После 16:00 открыть репозиторий согласно инструкции и проверить анонимный доступ к сдаваемой ветке. До такой проверки не утверждать, что анонимное клонирование уже подтверждено.

Проверенные хеши входных архивов:

- С эталоном: `52efa3738b406fff5e025ef57fb08fa31f616703398567e9f1b217c990df78f1`, 235054 байта.
- Без эталонов: `80693d40e670df1df7c24c4d5c92931960a3fe3fe912f16ce1ab9bb6f2ccbf51`, 694252 байта.

Первый набор содержит одну собственную обучающую запись LibriSpeech. Ни один из этих примеров не является test-clean/test-other и не служит оценкой итогового WER.
