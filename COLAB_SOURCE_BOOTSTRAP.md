# Установка Colab при недоступном anonymous Git clone

Основной notebook сохраняет 12 ячеек и единственное пользовательское поле DATASET_URL. Установочная ячейка поддерживает два способа получения исходников: клонирование сдаваемой ветки либо проверенный Git ZIP. Параметры источника и выпуска заполняет автор комплекта перед сдачей; пользователь их не подбирает.

Для архива необходимы четыре заполненные константы: SOURCE_ARCHIVE_URL, SOURCE_ARCHIVE_SHA256, RELEASE_MANIFEST_URL, RELEASE_MANIFEST_SHA256. Если источник задан без манифеста выпуска, установка останавливается с понятной ошибкой. Хеши проверяются до установки исходников и замены resources.json. Для скачивания используется зафиксированный gdown 5.2.0. Пока константы пусты, используется прежний git clone.

Установщик распаковывает Git ZIP во временную папку рядом с целевой и переносит её только после успешной проверки. Он отклоняет неверный SHA, абсолютные пути, выход через .., Windows-пути, дубли имён, символические ссылки и архивы больше 128 MiB после распаковки. Требуются настоящие train.py, inference.py, requirements.txt и src/asr/runtime.py. Существующий проект не перезаписывается. Манифест выпуска также сначала скачивается во временный файл; проверяются его SHA и согласованность model_sha256 с первым ресурсом модели.

Готовый резерв исходников: source.zip из проверенного промежуточного выпуска c0cb8d88a0d0ab27c5b7056c85ceb44ba1e9b1cf, 873722 байта, SHA-256 4b72a7c5a129b3080bc29073e91689bd15d89b122a271b99ac70648fb7304b3a. Приватная копия Drive: asr-source-c0cb8d8.zip, ID 1bocEIku_0uNRpu_JnUnE6fnZQm5pK3g7. У этого зафиксированного исходника тот же код инференса и модель, что у продолжающихся этапов; новое поведение установки исполняется непосредственно из финального notebook и не импортируется из старого ZIP. Архив не ссылается на собственный будущий SHA, поэтому циклической зависимости нет.

Архив источников и отдельный манифест остаются приватными во время обучения. После разрешённого срока публикации при финальной приёмке необходимо открыть именно нужные файлы, скачать их анонимно с повторной проверкой SHA и заполнить четыре константы. Новый манифест должен соответствовать выбранной по полным dev модели и декодеру. После этого требуется свежий Colab со всеми ячейками, с эталонами и без них; локальные тесты не заменяют эту проверку. Старые исполненные Colab e640 остаются доказательством прежней версии, а не нового bootstrap.

Проверки включают настоящий Git ZIP и исполнение фактической установочной ячейки notebook. В тесте архива запрещён вызов git clone; проверяется установленный исходник и отдельный манифест. Проверки неверного SHA и несовпадения идентификатора модели подтверждают сохранность уже установленного resources.json. Для чистого экспортированного дерева без .git тесты получают SHA-проверенный Git ZIP через ASR_SOURCE_TEST_ZIP. Команда полного набора: python -m pytest tests -q; сохранённые копии проекта в data/ и delivery/ не являются активным набором тестов.
